CSS bez zgadywania

selektory, layout i formatowanie z arkusza

Arkusz nie mówi „ustaw margin”. Mówi „marginesy zewnętrzne górny i dolny 10 px, pozostałe 50 px”. Ta ściąga tłumaczy takie zdania na gotowe reguły i pokazuje, gdzie kończy się wygląd, a zaczyna punkt.

Selektory i kaskada

Dobierz selektor dokładnie tak, jak mówi arkusz
SelektorCo wybieraPrzykład

elementwszystkie znaczniki danego typutable { width: 60%; }
.klasaelementy z klasą.miniatury { opacity: .8; }
#idjeden element z id#wynik { color: red; }

A:hoverA pod kursorema:hover { color: red; }
A:first-childpierwsze dziecko rodzicali:first-child { ... }

Kaskada i pierwszeństwo

Kolejność od najsilniejszego
  1. !important — unikaj, chyba że naprawdę trzeba
  2. styl w linii (style="...")
  3. #id
  4. .klasa, :hover, [atrybut]
  5. selektor znacznika
  6. *
Praktyczna zasada

Jeśli styl „nie działa”, najpierw sprawdź, czy selektor na pewno pasuje do elementu. Dopiero potem szukaj konfliktu w kaskadzie. W egzaminie najczęstszy błąd to kropka zamiast # albo odwrotnie.

✦

Skrót: „dla selektora tabeli” = table { ... }. „Dla klasy kontrolki” = .kontrolki { ... }. „Dla odnośników w menu” = nav a { ... } — nie samo a.

Łączenie selektorów — przykłady z arkuszy

wspólne cechy i wyjątki styl.css
/* wspólne dla nagłówka i stopki */
header, footer {
  background-color: #829EB9;
  color: white;
  text-align: center;
  padding: 10px;
}

/* tylko nagłówek */
header { height: 100px; padding: 2%; }

/* tylko blok boczny */
aside { width: 25%; height: 700px; line-height: 2; }

/* tylko odnośniki w menu */
nav a { font-weight: bold; color: #625B5B; }

/* tylko obraz w bloku środkowym */
.srodek img { width: 95%; border-radius: 8px; }

/* hover tylko na wierszach tabeli w bloku lewym */
.lewy tr:hover { background-color: ForestGreen; }

Box model, kolor i tekst

margin, padding, border — trzy słowa, które decydują o wyglądzie
Box model — od środka
margin — na zewnątrz
border — obramowanie
padding — wewnątrz
width × height — treść
Co mówi arkusz
  • marginesy wewnętrzne → padding
  • marginesy zewnętrzne → margin
  • obramowanie → border
  • szerokość / wysokość → width / height
  • zaokrąglenie rogów → border-radius

Shorthand vs longhand

PolecenieKod
marginesy zewnętrzne 10 px (wszystkie)margin: 10px;
górny i dolny 10 px, pozostałe 50 pxmargin: 10px 50px;
górny 10 px, prawy 20, dolny 30, lewy 40margin: 10px 20px 30px 40px;
tylko margines wewnętrzny górny 10 pxpadding-top: 10px;
margines zewnętrzny lewy 40 pxmargin-left: 40px;
marginesy automatycznie (środek)margin: 0 auto;
padding 2%padding: 2%;
!

Kolejność czterech wartości: góra → prawy → dół → lewy (zgodnie z ruchem wskazówek zegara). Dwie wartości: góra/dół, potem lewy/prawy. Trzy: góra, lewy/prawy, dół.

obraz za blokami — przykład z arkusza styl.css
img.motor {
  display: block;
  position: absolute;
  left: 15%;
  width: 70%;
  z-index: -1;       /* obraz jest zakryty przez bloki strony */
}

/* bloki, które mają być nad obrazem */
header, aside, main, footer {
  position: relative; /* tworzą własny kontekst nakładania */
  z-index: 1;
}
!

Position nie zastępuje layoutu. Do ustawienia bloków obok siebie używaj float, flex lub grid. position: absolute zostaw dla elementów, które naprawdę mają być wyjęte z przepływu — np. obraz w tle.

Trzy sposoby na układ bloków

Wybierz jeden i doprowadź do końca — komisja akceptuje każdy

W kryteriach R.3 wprost napisano: „np. float i clear albo display flex albo grid albo position". Nie ma jednego słusznego sposobu. Jest tylko wymóg, żeby bloki nie zachodziły na siebie i były zgodne z ilustracją.

!

Procenty szerokości w przykładach poniżej są PRZYKŁADOWE. Arkusz może wymagać innych wartości, np. header, main { width: 70% } zamiast 100%/75% — sprawdź dokładnie polecenia CSS w swoim arkuszu i dopasuj liczby. To samo dotyczy kolorów, marginesów i wysokości.

Wariant A — float + clear (najbardziej „szkolny”)

header + aside 25% + main 70% + footer styl.css
* { box-sizing: border-box; }

header, footer {
  clear: both;
  width: 100%;
}

aside {
  float: left;
  width: 25%;
  height: 700px;
}

main {
  float: left;
  width: 70%;
}

footer {
  clear: both;
}

Wariant B — flexbox (najszybszy dla dwóch kolumn)

kontener flex z zawijaniem styl.css
body {
  display: flex;
  flex-wrap: wrap;
}

header, footer { width: 100%; }
aside { width: 25%; }
main  { width: 70%; }

/* jeśli bloki są w kontenerze .strona */
.strona {
  display: flex;
  flex-wrap: wrap;
}
.strona header, .strona footer { flex: 0 0 100%; }
.strona aside { flex: 0 0 25%; }
.strona main  { flex: 1; }

Wariant C — grid (najbardziej odporny na błędy)

grid z obszarami — układ 2 kolumn styl.css
body {
  display: grid;
  grid-template-columns: 25% 70%;
  grid-template-areas:
    "header header"
    "aside  main"
    "footer footer";
}

header { grid-area: header; }
aside  { grid-area: aside; }
main   { grid-area: main; }
footer { grid-area: footer; }

/* trzy kolumny 25% / 50% / 25% */
/*
body {
  grid-template-columns: 25% 50% 25%;
  grid-template-areas:
    "header header header"
    "lewy   srodek prawy"
    "footer footer footer";
}
*/
✓

Okiem komisji (R.3): układ ma być zgodny z ilustracją i żaden blok nie może zachodzić na inny. Sprawdzaj w inspektorze, nie tylko „na oko" — szczególnie gdy używasz float bez clear.

aside {
  width: 25%;
  height: 700px;
  line-height: 2;
}

  padding-top: 10px;
}

/* 7. Blok sekcji */
section {
  border: 1px dashed DimGray;

  height: 400px;
  overflow: auto;

Jak ułożyć bloki — dopisz na końcu

grid dla układu z ilustracji styl.css
body {
  display: grid;
  grid-template-columns: 25% 75%;
  grid-template-areas:
    "header header"
    "aside  main"
    "footer footer";
  gap: 0;
}

header { grid-area: header; }
aside  { grid-area: aside; }
main   { grid-area: main; }
footer { grid-area: footer; }

/* jeśli w arkuszu blok główny ma 70%, a boczny 25%,
   ustaw grid-template-columns: 25% 70% i justify-content: center; */
!

Nie dodawaj stylów, których nie ma w arkuszu. Komisja nie karze za estetykę, ale dodatkowe margin czy padding mogą przesunąć bloki i zepsuć zgodność z ilustracją. Trzymaj się wymiarów z zadania.

Checklista CSS przed oddaniem

  • styl.css podłączony przez <link>
  • wszystkie formatowanie tylko w CSS
  • * { font-family: ... } — dokładna kolejność
  • wymiary bloków zgodne z ilustracją
  • bloki nie zachodzą na siebie
  • float ma clear, flex/grid ma poprawne wymiary
  • padding vs margin — dobrze przypisane
  • border-radius tylko tam, gdzie w arkuszu
  • overflow: auto dla sekcji z przewijaniem
  • .miniatury:hover zmienia opacity
  • transition jest na elemencie bazowym
  • selektory znaczników, jeśli arkusz tego wymaga
  • hover nie działa na zbyt szerokim selektorze
  • kolory dokładnie z arkusza (nazwa/hex/rgba)
  • font-family z cudzysłowami dla nazw ze spacją
  • line-height bez jednostki, jeśli tak w arkuszu
  • box-shadow: offset-x offset-y blur color
  • position: relative u rodzica dla absolute
  • z-index nie chowa treści pod tłem
  • strona wygląda jak ilustracja po odświeżeniu
✓

Najczęstsza strata punktów: styl jest w CSS, ale selektor nie pasuje do elementu w HTML. Otwórz inspektor (F12), kliknij element i sprawdź, czy reguła jest widoczna i przekreślona przez inną. To szybsze niż zgadywanie.
