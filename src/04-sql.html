SQL bez paniki

od treści polecenia do kwerendy i zrzutu

SQL to pierwszy rezultat oceniania (R.1). Cztery zapytania, jeden plik kwerendy.txt i cztery zrzuty ekranu. Ta ściąga tłumaczy każde zdanie z arkusza na konkretną klauzulę — od prostego SELECT po JOIN, GROUP BY i GRANT.

Wykonaj zapytania SQL działające na bazie islandia. Zapytania zapisz w pliku kwerendy.txt. Wykonaj zrzuty ekranu przedstawiające wyniki działania kwerend. Zrzuty zapisz w formacie PNG i nadaj im nazwy kw1, kw2, kw3, kw4. Zrzuty powinny obejmować cały ekran monitora z widocznym paskiem zadań.

01
rozdział 01

phpMyAdmin — import i zrzuty

Najpierw baza, potem kwerendy. Kolejność ma znaczenie
1
Utwórz bazę. W phpMyAdmin kliknij „Nowa baza”, wpisz nazwę dokładnie jak w arkuszu (np. islandia), wybierz zestaw znaków utf8_unicode_ci i kliknij „Utwórz”.
2
Zaimportuj tabele. Wybierz bazę → zakładka „Import” → „Wybierz plik” (np. baza1.sql) → „Wykonaj”. Nie zmieniaj formatu ani kodowania.
3
Zrzut importu. Zrób zrzut całego ekranu z widocznym paskiem zadań i listą tabel. Zapisz jako import w formacie wymaganym w arkuszu (JPEG lub PNG). Nie kadruj.
4
Wykonaj kwerendy. Zakładka „SQL”, wklej zapytanie, kliknij „Wykonaj”. Zrób zrzut wyniku z całym ekranem i paskiem zadań. Nazwij kw1, kw2, kw3, kw4.
5
Zapisz kwerendy. W pliku kwerendy.txt umieść wszystkie cztery zapytania, najlepiej z numerami i średnikiem na końcu.
Utworzenie bazy — SQL
CREATE DATABASE islandia
  CHARACTER SET utf8
  COLLATE utf8_unicode_ci;

Nazwa bazy musi być identyczna jak w poleceniu. Nie dodawaj polskich znaków w nazwie.

Co musi być na zrzucie
  • cały ekran monitora, bez kadrowania
  • widoczny pasek zadań Windows
  • widoczny wynik zapytania lub lista tabel
  • widoczne zapytanie, jeśli arkusz tego wymaga
  • dokładna nazwa pliku: kw1…kw4
  • format zgodny z arkuszem: JPEG albo PNG
  • liczba rekordów na zrzucie musi się zgadzać — np. 9, 1, 4 i 8 dla Islandii

Jak zapisać kwerendy.txt

czytelny plik z czterema zapytaniami kwerendy.txt
-- Zapytanie 1
SELECT idObiekt, plik, nazwa FROM obiekty WHERE panstwo = 'Islandia';

-- Zapytanie 2
SELECT plik, nazwa, nazwaCechy, wartoscCechy, opis, rodzaj
FROM obiekty JOIN rodzaje USING(idRodzaj)
WHERE idObiekt = 46;

-- Zapytanie 3
SELECT nazwa FROM obiekty
WHERE idRodzaj = 10 AND panstwo = 'Islandia';

-- Zapytanie 4
SELECT rodzaj, COUNT(obiekty.idObiekt) AS `Liczba obiektów`
FROM rodzaje JOIN obiekty USING(idRodzaj)
GROUP BY rodzaj;
!

Nie zostawiaj domyślnej nazwy zrzutu. System może zapisać Zrzut ekranu 2026-06-01 120000.png. Zmień nazwę na kw1.png (lub kw1.jpg) — komisja szuka dokładnie takich plików.

✦

Kolejność plików: import dotyczy importu, a kw1–kw4 dotyczą zapytań 1–4. Nie numeruj zrzutów według kolejności robienia, tylko według numeru zapytania.

Gdy import się nie uda
  • nie wybrano bazy przed importem — najpierw kliknij jej nazwę w lewym panelu
  • plik nie jest plikiem SQL — sprawdź rozszerzenie i zawartość
  • komunikat o kodowaniu — ustaw utf8_unicode_ci i zaimportuj ponownie
  • import częściowy — usuń tabele i powtórz import od nowa

SELECT, WHERE, ORDER BY, LIMIT

Kolejność klauzul jest stała — naucz się jej raz
szkielet każdego zapytania kwerendy.txt
SELECT kolumna1, kolumna2
FROM tabela
JOIN inna_tabela ON tabela.id = inna_tabela.id_tabeli
WHERE warunek
GROUP BY kolumna
HAVING warunek_na_grupach
ORDER BY kolumna ASC|DESC
LIMIT liczba;

Dokładne zapytania z arkuszy

2026 czerwiec — baza islandia kwerendy.txt
-- 1. obiekty na Islandii
SELECT idObiekt, plik, nazwa
FROM obiekty
WHERE panstwo = 'Islandia';

-- 2. szczegóły obiektu 46 + rodzaj
SELECT plik, nazwa, nazwaCechy, wartoscCechy, opis, rodzaj
FROM obiekty
JOIN rodzaje USING(idRodzaj)
WHERE idObiekt = 46;

-- 3. nazwy obiektów rodzaju 10 na Islandii
SELECT nazwa
FROM obiekty
WHERE idRodzaj = 10 AND panstwo = 'Islandia';

-- 4. liczba obiektów każdego rodzaju
SELECT rodzaj, COUNT(obiekty.idObiekt) AS `Liczba obiektów`
FROM rodzaje
JOIN obiekty USING(idRodzaj)
GROUP BY rodzaj;
2025 czerwiec — baza gry kwerendy.txt
-- 1. wszystkie gry: id, nazwa, zdjęcie
SELECT id, nazwa, zdjecie FROM gry;

-- 2. gra nr 1: pierwsze 100 znaków opisu
SELECT nazwa, LEFT(opis, 100), punkty, cena
FROM gry
WHERE id = 1;

-- 3. pięć gier z najwyższą punktacją
SELECT nazwa, punkty
FROM gry
ORDER BY punkty DESC
LIMIT 5;

-- 4. nowy wiersz — dane skopiuj z rekord.txt
INSERT INTO gry (nazwa, opis, punkty, cena, zdjecie)
VALUES ('tytuł', 'opis', 0, 0.00, 'plik.jpg');
!

„Jedynie pola” oznacza, że nie wolno użyć SELECT *. Wypisz dokładnie te kolumny, które podaje arkusz, w tej samej kolejności. Nadmiarowa kolumna może przekreślić punkt.

✓

Okiem komisji (R.1): zapytanie ma być uniwersalne dla każdego zestawu danych — warunki mają wynikać z treści zadania, a nie z konkretnych rekordów, które akurat widzisz. Na zrzucie musi być widoczny poprawny wynik.

JOIN i GROUP BY

„Posłuż się relacją” = połącz tabele po kluczu

Relacja w bazie to wspólne pole w dwóch tabelach. Najczęściej klucz główny jednej tabeli pojawia się jako klucz obcy w drugiej. W SQL łączysz je przez JOIN — po nazwie pola (USING) albo po warunku (ON).

Wariant A — USING
SELECT o.nazwa, r.rodzaj
FROM obiekty AS o
JOIN rodzaje AS r
  USING(idRodzaj);

Gdy kolumna w obu tabelach nazywa się tak samo.

Wariant B — ON
SELECT o.nazwa, r.rodzaj
FROM obiekty AS o
JOIN rodzaje AS r
  ON o.idRodzaj = r.idRodzaj;

Gdy nazwy kluczy są różne albo chcesz jawnie pokazać warunek.

Grupowanie i zliczanie

liczba obiektów każdego rodzaju — 2026 czerwiec kwerendy.txt
SELECT rodzaj, COUNT(obiekty.idObiekt) AS `Liczba obiektów`
FROM rodzaje
JOIN obiekty USING(idRodzaj)
GROUP BY rodzaj;
PolecenieFunkcjaUwaga
zliczające liczbę wierszyCOUNT(*)liczy wszystkie wiersze
zliczające liczbę obiektówCOUNT(idObiekt)pomija NULL-e
średnia cenaAVG(cena)wynik może mieć wiele miejsc
najdroższy / najwyższa wartośćMAX(cena)nie myl z ORDER BY … LIMIT 1
najtańszy / najniższa wartośćMIN(cena)
sumaSUM(cena)
pierwsze 100 znakówLEFT(opis, 100)funkcja tekstowa MariaDB
zaokrąglenie średniejROUND(AVG(cena), 2)dwa miejsca po przecinku
średnia i maksymalna cena — 2026 styczeń kwerendy.txt
SELECT
  AVG(cena) AS `Średnia cena`,
  MAX(cena) AS `Maksymalna cena`
FROM pojazdy
WHERE model = 'meta';
pojazdy i kolory — JOIN po kluczu kwerendy.txt
SELECT marka, model, cena, nazwa, doplata
FROM pojazdy
JOIN kolory ON kolor = kolory.id
WHERE model = 'alfa';
!

GROUP BY musi zawierać wszystkie zwykłe kolumny z SELECT. Jeśli wybierasz rodzaj i liczysz obiekty, grupuj po rodzaj. W przeciwnym razie MariaDB może zwrócić błąd albo nieprzewidywalny wynik.

✦

Alias z odstępem: AS `Liczba obiektów` — w backtickach, nie w cudzysłowach prostych. Backtick to znak pod tyldą (~) na klawiaturze. W oficjalnych zasadach dopuszczają też cudzysłowy, ale backtick jest najbezpieczniejszy.

INSERT, UPDATE, ALTER, konta

Cztery typy poleceń, które nie są SELECT-em

INSERT — dodanie wiersza

dane z pliku rekord.txt — 2025 czerwiec kwerendy.txt
INSERT INTO gry (nazwa, opis, punkty, cena, zdjecie)
VALUES ('tytuł gry', 'opis z pliku', 85, 49.99, 'obraz.jpg');
!

Klucz główny nadawany automatycznie — nie podawaj kolumny id w INSERT, jeśli jest AUTO_INCREMENT. Wartości tekstowe w cudzysłowach prostych, liczby bez cudzysłowów, kropka dziesiętna zamiast przecinka.

UPDATE — zmiana istniejącego wiersza

zawsze z WHERE — inaczej zmienisz całą tabelę kwerendy.txt
UPDATE produkty
SET cena = 129.99, promocja = 1
WHERE id = 7;
!

UPDATE bez WHERE zmienia wszystkie wiersze. To najgroźniejszy błąd w SQL. Przed wykonaniem sprawdź warunek przez SELECT * FROM tabela WHERE ...;.

ALTER TABLE — zmiana struktury

dodanie kolumny — 2024 i 2023 czerwiec kwerendy.txt
-- kolumna ocena typu całkowitego
ALTER TABLE wycieczki ADD ocena INT;

-- kolumna informacje typu tekstowego
ALTER TABLE dostawcy ADD informacje TEXT;

-- limit 0–255 — typ TINYINT UNSIGNED
ALTER TABLE Ryby ADD dobowy_limit TINYINT UNSIGNED;
PolecenieTyp kolumny
typ całkowityINT
liczba z zakresu 0–255TINYINT UNSIGNED
krótki tekstVARCHAR(255)
długi tekstTEXT
dataDATE
cena / kwotaDECIMAL(10,2)

DELETE — usuwanie wierszy

zawsze z WHERE — inaczej usuniesz całą tabelę kwerendy.txt
DELETE FROM produkty
WHERE id = 7;

-- usunięcie wszystkich starszych niż 2020
DELETE FROM wycieczki
WHERE data < '2020-01-01';
!

DELETE bez WHERE usuwa wszystkie wiersze. Tabela zostaje pusta, ale jej struktura istnieje. Jeśli chcesz usunąć też strukturę, użyj DROP TABLE nazwa;.

CREATE VIEW — widok

zapisane zapytanie działające jak tabela kwerendy.txt
CREATE VIEW ObiektyIslandii AS
SELECT idObiekt, nazwa, plik
FROM obiekty
WHERE panstwo = 'Islandia';

-- potem można go użyć jak zwykłej tabeli
SELECT idObiekt, nazwa FROM ObiektyIslandii;

Funkcje dat — DATEDIFF, LIKE, CURRENT_DATE

różnica dni i filtrowanie po dacie kwerendy.txt
-- różnica dni: koniec - początek
SELECT nazwa, DATEDIFF(koniec, poczatek) AS dni_trwania
FROM wycieczki;

-- filtry po dacie
SELECT nazwa, data_rezerwacji FROM rezerwacje
WHERE data_rezerwacji LIKE '2020-07%';     -- lipiec 2020

SELECT nazwa, data_rezerwacji FROM rezerwacje
WHERE data_rezerwacji >= CURRENT_DATE;    -- od dziś

-- dodawanie/odejmowanie dni
SELECT nazwa, DATE_ADD(poczatek, INTERVAL 7 DAY) AS tydzien_po
FROM wycieczki;

CREATE USER i GRANT — 2025 styczeń

konto Marek i prawa tylko do produktu kwerendy.txt
-- 1. utwórz konto
CREATE USER 'Marek'@'localhost' IDENTIFIED BY 'M@reK';

-- 2. nadaj tylko SELECT i UPDATE w bazie obuwie, tabela produkt
GRANT SELECT, UPDATE ON obuwie.produkt TO 'Marek'@'localhost';
✦

Kolejność: najpierw CREATE USER, potem GRANT. Nazwa użytkownika i host muszą być w cudzysłowach: 'Marek'@'localhost'. Uprawnienia pisz wielkimi literami i oddziel przecinkiem: SELECT, UPDATE.

✓

Okiem komisji (R.1): konto musi być utworzone na localhost z podanym hasłem, a GRANT ma przyznawać jedynie wymienione prawa i tylko wskazanej tabeli. Samo GRANT ALL nie spełnia polecenia „jedynie do przeglądania i aktualizacji".

✦

Kodowanie na egzaminie vs. własne projekty. Arkusz 2026 wymaga utf8_unicode_ci — trzymaj się arkusza. We własnych projektach współczesny MySQL zaleca utf8mb4, bo utf8 to przestarzały alias utf8mb3.
